server/websocket.ts currently creates a second HTTP server via createServer(app), exposes unauthenticated user:join and conversation/message events, persists messages through getDb, and returns that server. server/_core/index.ts already owns the canonical HTTP server and must attach Socket.io there rather than calling setupWebSocket(app) unchanged. client useWebSocket defaults to VITE_API_URL or localhost:3000 and expects conversation:join, message:send, messages:read, typing:start/end, and message:received events. The current client does not send auth credentials or a user:join event, so startup wiring should be additive and avoid claiming authorization until the handshake contract is upgraded.
