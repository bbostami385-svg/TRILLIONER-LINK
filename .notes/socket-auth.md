The existing SDK authenticates requests by parsing COOKIE_NAME from req.headers.cookie, verifying the JWT session cookie, loading/upserting the user by openId, and returning the database user. Socket.io handshake headers expose the same cookie header, so the server can construct a minimal Request-like object and call sdk.authenticateRequest during io.use middleware. This avoids trusting auth.userId from the browser. Conversation membership can then be checked against the existing conversations table before joining or writing messages.
